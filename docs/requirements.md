# 校园咖啡在线点单系统 - 需求规格说明书 (PRD)

## 1. 项目简介 (Project Overview)
本系统旨在解决高中校园咖啡厅在课间休息时段排队拥堵、点单效率低的问题。通过构建一套基于 Web 的在线点单系统，让学生利用个人 iPad 提前下单，咖啡师通过管理端接单制作，实现“线上下单、到店即取”的高效流转。

## 2. 核心业务流程 (Core Workflow)
1.  **学生** 登录系统 -> 浏览菜单 -> 下单支付 -> 获得取餐号 -> 到店取餐。
2.  **咖啡师** 接收订单 -> 制作咖啡 -> 修改订单状态（制作完成） -> (如有异常) 处理退款。

## 3. 用户角色与权限 (User Roles)

| 角色 | 描述 | 终端设备 | 核心功能 |
| :--- | :--- | :--- | :--- |
| **学生 (Student)** | 咖啡消费者 | 个人 iPad (网页) | 登录(改密)、浏览菜单、下单、钱包支付、查看排队状态 |
| **咖啡师 (Barista)** | 制作与管理人员 | 柜台平板/电脑 | 接单管理(查看/完成)、**处理退款**、账户充值 |
| **管理员 (System Admin)** | 系统维护 | 电脑 | 菜单管理(上新/改价)、销售报表、账户管理 |

## 4. 功能需求详情 (Functional Requirements)

### 4.1 学生端 (Student Portal) - iPad Web
**设计重点**：适配 iPad 触控交互，响应快速。

#### 4.1.1 账户与安全
*   **初始登录**：使用学校分配的统一账号（如学号）和初始密码登录。
*   **强制改密**：首次登录后必须修改密码方可使用，保障账户安全。
*   **外部账户对接 (External Account)**：
    *   **余额不存储在本地**：系统实时调用学校外部 API 查询学生账户余额。
    *   **余额展示**：首页调用接口展示当前外部账户余额。

#### 4.1.2 点单流程
*   **菜单浏览**：
    *   大图卡片式展示，适配 Pad 屏幕。
    *   支持多规格选择（冷/热、糖度、杯型）。
*   **高并发处理 (Critical)**：
    *   系统需支撑课间 10-15 分钟内的高并发访问与下单。
    *   使用排队机制或锁机制防止超卖与数据冲突。
*   **支付结算**：
    *   点击支付时，后端调用外部 API 扣除金额。
    *   若外部接口返回“余额不足”，提示学生充值（需前往学校充值点）。

#### 4.1.3 订单追踪
*   **实时状态**：显示“前方排队 N 单”或“预计等待 M 分钟”。
*   **取餐凭证**：生成高亮的大字体取餐码（如 A-15）。

### 4.2 咖啡师/管理端 (Barista Dashboard)
**设计重点**：信息一目了然，操作路径极短。

#### 4.2.1 订单队列管理
*   **接单看板**：
    *   实时刷新新订单，伴有(可选)提示音。
    *   按时间顺序排列，优先展示最早的订单。
    *   卡片显示：取餐号、商品详情（高亮特殊规格，如“去冰”）、下单人。
*   **状态操作**：
    *   **一键完成**：点击制作完成，通知学生端（状态变更）。

#### 4.2.2 售后与退款
*   **退款流程**：
    *   学生无法自行退款。
    *   如遇缺货或学生下错单，需到柜台沟通。
    *   咖啡师在管理端找到对应订单，点击【退款】按钮，**调用外部API**将资金退回学生账户。

#### 4.2.3 (已移除) 充值管理
*   资金管理完全依赖学校外部系统，本系统不具备充值功能。

## 5. 非功能需求 (Non-functional Requirements)

1.  **高并发性能 (High Concurrency)**
    *   场景：课间休息（Break Time）全校学生集中访问。
    *   要求：API 响应需在 200ms 内；数据库需能处理瞬间大量写入（下单、扣款）。
    *   *技术建议：后端采用异步架构 (FastAPI)，数据库通过事务保证扣款准确性，可引入 Redis 缓存菜单与简易消息队列。*
2.  **界面适配 (UI/UX)**
    *   针对 **iPad Safari/Chrome** 浏览器优化分辨率与触控手势。
    *   避免复杂的下拉菜单，尽量使用平铺的按钮选项。
3.  **稳定性**
    *   断网或刷新页面后，需能恢复当前操作状态（如购物车不丢失）。

## 6. 数据字典与逻辑 (Logic & Data)
*   **订单状态机**：`已支付(Created)` -> `制作中(Processing)` -> `已完成/待取(Ready)` -> `已取餐(Completed)` | `已退款(Refunded)`
